Claude Code · 官方字段对照

配置键中文手册

把 settings.json 与 ~/.claude.json 的官方键翻成中文。英文键名、路径、枚举保持原文。未在官方文档写明的值不会猜。

这是另一份文件

官方写明：Claude Code 会自己写 ~/.claude.json。它保存登录会话、MCP 服务器、每个项目的信任状态，以及 /config 写入的一小撮全局配置键。

不要把密钥、OAuth token 或真实的 ~/.claude.json 贴到网页或仓库。本页只收录官方 Global config settings 列出的键。

  • 登录会话与 token：官方由 CLI 自己写，本页不展示任何示例。
  • 个人 MCP：可用 claude mcp add --scope user，会写到这份文件，而不是项目 .mcp.json。
  • 这些键放进 settings.json 会被忽略。

两份文件怎么对照

  1. 用户 ~/.claude/settings.json — 你在这台机器的每个项目。
  2. 项目共享 .claude/settings.json — 提交后全员生效。
  3. 项目本地 .claude/settings.local.json — 只影响你在这个项目；通常不进 git。
  4. 托管 managed-settings.json / MDM / claude.ai 控制台 — 组织策略，你改不掉（少量安全例外除外）。
  5. 全局配置 ~/.claude.json — 不是 settings 文件；只放官方 Global config 键和 CLI 自己写的状态。

优先级（高 → 低）

  1. 1
    托管设置managed-settings.json、MDM 或 claude.ai 控制台
  2. 2
    命令行--settings / 启动标志，只影响这一次会话
  3. 3
    项目本地.claude/settings.local.json
  4. 4
    项目共享.claude/settings.json
  5. 5
    用户~/.claude/settings.json

环境变量不是这一叠里的一层。某个键和某个变量谁赢，以该键的官方条目为准。

列表通常合并

同一列表键（例如 permissions.allow）出现在多个文件时，Claude Code 一般会合并，而不是只留一份。

官方点名的例外：

  • fallbackModel 是有顺序的链，取最高优先级文件里的整份值，不合并。
  • modelPicker 也不合并。只从托管、--settings、用户设置里取最高的一份；项目和本地文件里的该键会被忽略。
  • 托管来源一旦定义 availableModels，就按托管名单原样生效，不再合并你在用户 / 项目 / 本地里加的条目。

仓库文件里会被忽略的范围

Scope 若是「用户或托管」「用户 / 本地 / 托管」「仅托管」「仅 ~/.claude.json」，共享的 .claude/settings.json 通常不会生效。官方例外：autoContinueAtUsageLimit 仍可被仓库文件关掉。
